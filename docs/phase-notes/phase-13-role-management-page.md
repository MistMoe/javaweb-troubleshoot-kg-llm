# Phase 13 角色管理页与历史页样式隔离

## 本步目标

本阶段完成两件事：

1. 彻底修复分析历史页中“复盘详情”和“技术栈分布”重叠的问题。
2. 完成最后一个业务页面：角色管理页。

## 分析历史页返修

问题表现：

- 分析历史页右侧“复盘详情”卡片压在“技术栈分布”上。
- 上一次已改成 `grid-template-areas`，但页面刷新后仍然不稳定。

根因：

- `HistoryView.vue` 原来用 `import './history-view.css'` 引入样式，属于全局 CSS。
- 其他页面也有同名类，例如：
  - `.filter-card`
  - `.detail-card`
- 页面切换后，不同页面的全局 CSS 会互相覆盖，导致历史页的布局规则被其他页面同名类影响。

修复：

- 移除历史页脚本中的全局 CSS import。
- 改为：

```vue
<style scoped src="./history-view.css"></style>
```

这样历史页样式会带组件作用域，不再和知识库页、用户页等同名 class 串样式。

## 角色管理页是做什么的

角色管理页不是登录页面，也不是给用户改密码的页面。

在当前系统里：

- 用户管理页：维护账号，并给账号分配角色。
- 角色管理页：说明每种角色的权限边界，以及登录后能看到哪些页面。

它用于展示 RBAC（基于角色的访问控制）的逻辑：

- `ADMIN`：系统管理员，可以维护用户、知识库、查看全部分析历史和角色说明。
- `MAINTAINER`：知识库维护员，可以维护故障知识库、同步 Neo4j、查看全局分析历史。
- `USER`：普通用户，可以提交智能排障、查看知识图谱、查看自己的分析历史。

## 新增前端页面

新增：

- `frontend/src/views/roles/RoleManagementView.vue`
- `frontend/src/views/roles/role-management-view.css`

页面包含：

1. 顶部说明区：解释角色管理页用途。
2. 角色统计区：系统角色数、菜单节点数、权限层级。
3. 角色卡片：展示 ADMIN / MAINTAINER / USER 的说明。
4. 权限矩阵：展示每个页面对不同角色是否可见。
5. 登录展示逻辑：账号登录、读取角色、过滤菜单。
6. 设计边界：说明当前课程版本使用固定三角色，不开放删除角色。

## 数据来源

角色管理页调用现有接口：

```http
GET /api/users/roles
```

权限矩阵目前在前端静态配置，和 AppShell 菜单权限保持一致。这样能更直观地展示系统权限设计，也避免课程演示时误改角色导致菜单混乱。
