# 个人资料账户工作区设计

## 目标

将现有只读、卡片堆叠式个人资料页改造成三个角色均可使用的真实账户工作区。页面需要突出当前身份和资料编辑，不改变登录注册页、全局导航、角色权限或其他业务页面。个人资料页采用独立的平面冷白设计，不延续系统业务页的浮雕卡片材质。

## 页面结构

页面采用一个连续的双栏工作区，不再把账号、角色、统计、活动和快捷入口拆成多张独立卡片。

- 左侧身份栏：头像字标、显示名称、用户名、角色、账号状态，以及分析、收藏、投稿三项紧凑数据。
- 右侧主工作区：基本资料、安全设置、最近活动三个连续章节，章节之间使用留白和极细分隔线。
- 基本资料：用户名只读，昵称和邮箱可编辑并真实保存。
- 安全设置：原密码、新密码、确认新密码；修改密码必须校验原密码。
- 最近活动：继续整合分析记录、收藏和经验投稿，使用轻量时间流而非独立卡片。
- 快捷入口：改为低强调文字入口，融入身份栏底部，不再占据单独面板。

## 视觉规则

- 延续系统的浅蓝灰、冷白和低饱和蓝色系，保证从其他页面进入时色彩过渡自然。
- 使用平面冷白底、细线边界、大块留白和明确的文字层级，不使用浮雕阴影，也不把章节拆成“一张一张卡片”。
- 左侧身份栏使用极浅蓝色块与右侧编辑区形成结构区分，但不使用渐变或悬浮卡片效果。
- 主操作“保存资料”使用蓝色按钮；“重置”与密码修改保持次级视觉。
- 使用清晰的编辑状态、保存状态和错误提示，不添加渐变、星芒或复杂动画。
- 桌面端双栏，窄屏改为上下结构，不能横向溢出。

## 后端接口

在认证域新增当前用户自助接口，身份由现有 Bearer 会话令牌确定，不接收前端传入的用户 ID。

### 更新基本资料

`PUT /api/auth/profile`

请求字段：

- `nickname`：允许为空，保存前去除首尾空格。
- `email`：允许为空；有值时校验基本邮箱格式。

接口只更新当前账号的昵称和邮箱，不允许修改用户名、状态或角色。成功后同步刷新服务端当前会话中的 `UserProfile` 并返回新资料。

### 修改密码

`PUT /api/auth/password`

请求字段：

- `currentPassword`
- `newPassword`

规则：原密码必须匹配；新密码至少 6 位；新旧密码不能相同。成功后更新数据库密码。当前课程项目沿用现有明文密码机制，不在本步骤扩展密码哈希迁移，以免破坏已有演示账号。

## 前端数据流

1. `ProfileView` 从 `currentUser` 初始化资料表单。
2. 保存基本资料时携带全局 token 调用自助资料接口。
3. 成功后组件触发 `profile-updated`，`App.vue` 更新 `currentUser`，顶部用户区和个人页立即同步。
4. 修改密码成功后清空三个密码输入框；失败时保留输入并显示明确原因。
5. 统计接口互相独立，某一接口失败不阻塞资料编辑。

## 权限与边界

- `ADMIN`、`MAINTAINER`、`USER` 均可修改自己的昵称、邮箱和密码。
- 用户名、账号状态、角色只读。
- 个人资料接口不能通过参数修改其他用户。
- 缺少或无效 token 返回 401；校验失败返回 400；原密码错误返回 400。

## 错误处理

- 前端禁止昵称或邮箱未变化时重复提交。
- 邮箱格式、新密码长度和两次密码一致性先在前端校验，后端再次校验。
- 保存期间按钮进入 loading，防止重复请求。
- 错误提示优先使用后端返回消息，网络异常显示通用提示。

## 测试与验收

- 后端测试覆盖：无令牌、资料更新成功、邮箱格式错误、原密码错误、密码更新成功。
- 前端 UI 契约覆盖：连续工作区、身份栏、资料表单、安全区、保存按钮和响应式结构。
- 运行 Maven 相关测试、前端 UI 契约测试和 Vite 构建。
- 验收时确认三个角色均能进入页面；昵称和邮箱保存后顶部同步；密码修改后新密码可登录；用户名、角色和状态不可编辑。

## 非目标

- 不实现头像文件上传。
- 不允许自行修改用户名、角色或账号状态。
- 不进行全项目密码哈希迁移。
- 不修改登录页、注册页或其他业务页面布局。
